# 言葉帖 (Kotoba-Chō) — 产品文档

> *词汇即理解，而非闪卡。*

---

## 1. 产品愿景

「言葉帖」是一款面向 JLPT 学习者的日语单词学习应用。它与 Mojitest、百词斩等既有产品采用截然不同的设计哲学。

### 1.1 既有产品的问题

绝大多数单词应用把"看单词、四选一选意思"当作学习。但这远远不够：

- **搭配（コロケーション）**——「題名」配「つける」还是「書く」？
- **近义词辨析**——「題名 / タイトル / 表題」意思接近但用法不同
- **使用频率与语域**——哪些是书面语，哪些是日常口语？

JLPT 尤其是 N2 以上，真正的难点正是这些。

### 1.2 本产品的差异化思路

#### 「先理解，后练习」

学习一个新单词时，首先静下心读一页"单词图鉴"，包含：

- 三条覆盖不同语境的例句
- 常用搭配
- 近义词辨析
- 使用频率与语域说明
- 一句话使用提示

读完后再进入练习。这个阶段不催促，不计时。

#### 三维度习熟度模型 ⭐ 核心差异化点

不用"会了/不会"的二元划分，而是用**三个相互独立的习熟次元**：

| 次元 | 名称 | 含义 |
|---|---|---|
| **R** | 認識（Recognition） | 看到/听到单词能想起意思 |
| **P** | 産出（Production） | 知道意思能写出/选出单词 |
| **U** | 運用（Usage） | 在句子里正确使用，能识别误用 |

**软依赖解锁机制**：
- R 始终开放
- R 稳定（stability ≥ 3 天）后 P 解锁
- P 稳定后 U 解锁

这让学习按照"识别 → 主动回忆 → 灵活运用"的认知科学路径渐进，而不是无差别死记硬背。

> ⚠️ **关键 UI 要求**：界面上出现 R/P/U 时，必须配以日文全称（認識・産出・運用）和说明，让用户立刻理解。这是本产品最大的差异点，如果用户看不懂这三个字母，整个差异化卖点就失效了。

### 1.3 三个设计原则

#### 原则 1：静謐 — 学习需要专注

不用花哨的徽章、连胜数字、达成音效。Duolingo 式的"游戏化"会分散单词学习所需的专注力。

UI 参照设计精良的纸质字典、《暮しの手帖》《婦人之友》等日本生活美学杂志的版式。

#### 原则 2：緻密 — 一字一字慎重对待

不追求单词数量，每个词条要"立得住"。Library 页面里每个词都应该有自己的人格，不是流水线上的卡片。

#### 原则 3：漸進 — 不急，让其遗忘，再相遇

基于 FSRS-like 间隔重复，在记忆即将消退时再次出现。即使用户想加速，系统也会平静地说"明天再来"。

## 2. 学习体验流程

### 2.1 一日的流程

```
首页（今日预定）
   │
   ▼
新单词的 Learn 页 ──────────┐
   │                          │ Round 1（学一个测一个）
   ▼                          │
新单词的 Practice ──────────┘
   │
   ▼
（重复学完所有新单词）
   │
   ▼
Round 1 完成 → 第二回 (Round 2) 入场页
   │
   ▼
所有新单词用不同的题再测一遍（顺序打乱）
   │
   ▼
已学单词的复习题（多维度交错）
   │
   ▼
本日 Summary
```

**辅流：単語別練習（单词练习模式）**
单语帳（Library）词条 drawer →「打开学习页 →」（带 `?from=library`）→ 学习页底部「練習する →」按钮 → 针对单个词把题库里的所有题（含未解锁维度）走一遍。队列状态完全不持久化，结果不计入 SRS。给「我就想攻克这一个词」的用户场景使用。注意：library 路径下学习页会隐藏首日新词专用提示「よく読んでください…」与「理解した — 練習へ」按钮，避免重复触发 R 维度学习。

### 2.2 两轮制（Two-Round Method）

新单词的当日学习结合两种认知科学效应：

- **Round 1（即时测试效应）**：学完立刻测，强化初始记忆痕迹
- **Round 2（间隔检索效应）**：在所有新词学完后再次测试，且**用不同的题目**，强化巩固

### 2.3 多维度 SRS 调度

- 每对 (单词, 维度) 维护独立的 FSRS-like 参数（stability、difficulty、last_review、next_due）
- 复习时从所有到期的 (单词, 维度) 对中构建队列
- 维度交错（避免 R 题和 P 题成块出现）
- U 题答对时给 R/P 一点小奖励（× 1.05）；答错给小惩罚（× 0.95）

## 3. 题型设计

| 主维度 | 类型 | 形式 | 示例 |
|---|---|---|---|
| R | `kanji_to_meaning` | 看汉字选意思 | 「題名」的意思是？ |
| R | `context_inference` | 给一段不含目标词的描述，反推该用哪个词 | 「父亲一旦决定就 30 年不变」→ 頑固 |
| R | `listening_kanji` | 听音选汉字（4 选 1，干扰项由 LLM 生成读音相近词；选项不带假名） | 听 「だいめい」 → 題名 / 大名 / 提案 / 代案 |
| P | `meaning_to_kanji` | 看意思选汉字 | 「（作品的）题名、标题」用日语怎么说？ |
| U | `cloze` | 完形填空 | 「応募する小説の____がなかなか決まらず」→ 題名 |
| U | `synonym_replacement` | 句子里某词最自然的替换 | 「あの映画の<u>題名</u>」最自然替换为？ |
| U | `wrong_usage` | 4 个用例中选出用法错误的一个 | 「彼の題名は山田太郎だ」是错误用法 |

`listening_kanji` 的选项是规则 2「汉字必须配假名」的明文例外——为了不泄露读音、保住听辨难度，选项刻意保留为裸汉字。详见 `CLAUDE.md` 规则 2。

### 将来题型（未实现）

- `sentence_arrangement` — 句子重组（JLPT 文法常考）
- `dictation_kanji` — 假名 → 汉字（IME 输入）
- `dictation_listening` — 听音写词（自由输入版，区别于已实现的 4 选 1 `listening_kanji`）
- `sentence_writing` — 用指定词造句 + AI 批改
- `translation` — 中→日翻译 + AI 批改

## 4. 语言文案规范 ⭐

### 4.1 日语区与中文区的划分

UI 文案明确分两区：

**日语区（保持日语）**
- 首页、学习页、练习页、Round2、单词帖卡面、今日总结
- 顶部导航 Masthead（首页 / 学ぶ / 単語帳 / 今日のまとめ / 設定 等）
- 运行时提示（加载中、错误、空状态）—— 属于学习氛围的一部分
- R/P/U 维度名（認識・産出・運用）

**中文区（用中文）**
- 设置页（含开发者模式）
- Library 词条 drawer 内的管理动作（3 档掌握度按钮、关闭、打开学习页等）
- 内部错误页 / 调试页（若有）

**数据字段（按规则不变）**
- `meaningZh`、例句的中文翻译——本来就是中文
- 缩略字母 R / P / U——首次出现必须配日文全称（認識・産出・運用）

判断原则：**面向"使用产品学习"的用户用日语营造沉浸；面向"配置/管理产品"的动作用中文降低操作门槛**。新增文案前先判断属于哪一区。

### 4.2 假名注音（フリガナ）

**所有出现汉字的地方必须配假名注音**。这是面向日语学习者的应用最基本的素养。

❌ 错误示范：
```
「題名」を使った文を作りなさい
```

✅ 正确示范：
```
「題名（だいめい）」を使った文を作りなさい
```

或使用 ruby 标签：
```html
<ruby>題名<rt>だいめい</rt></ruby>
```

应用范围：
- 单词主页面已经有大字号汉字 + 假名标注（已实现）
- 例句、选项、解析中的所有 N2-N1 级别汉字必须加注
- 题干、按钮文字中的汉字也要加注（除非该词在用户当前等级以下，可视为已掌握）

### 4.3 R / P / U 的宣传与说明

这不只是缩写，而是产品的核心差异化点。必须在以下位置明确展示：

1. **首页 Lead 文案**：突出"認識・産出・運用三次元"的存在
2. **Library 页**：首次访问时显示三维度说明卡
3. **Practice 题目页**：维度 Pill 标签上 hover/tap 显示 tooltip
4. **首次启动 Onboarding**：用一整页讲清楚（未实现）
5. **首页副标题或导航附近**：常驻一句简介，让新用户随时能看到
6. **Practice 题目页 popover 快速标记**：题目页 header 提供「習得度」按钮，点击弹出轻量 popover，直接调整当前词的 R / P / U 三维度掌握档位（未学 / 学习中 / 精通）。复用 Library drawer 的三档管理控件，无需中断练习返回 Library。文案规则同 drawer——管理动作 → 中文区，触发器 → 日语 chrome。

## 5. 多 JLPT 等级支持 ⭐

### 5.1 扩展方向

当前原型只支持 N2，但设计上要预留 **N5 / N4 / N3 / N2 / N1** 全五级。

### 5.2 数据结构

```javascript
// 单词数据
{
  word: "題名",
  furigana: "だいめい",
  level: 2,            // 1 ~ 5 整数（注：JLPT 数字越小越难）
  // ...
}
```

`level` 字段已存在，但 UI 上目前固定显示「N2」。改造为：

- 用户在设置中选择目标等级（可多选，例：「N3 + N2 同时学习」）
- Library 加等级筛选器
- 首页分等级显示进度（「今天 N2: 4 个新词，N3: 2 个复习」）
- 各等级独立统计

### 5.3 跨等级逻辑

某些单词可能跨等级（词表边界本来就模糊）。处理：
- 数据上保留**最低等级**
- 用户标记「N2 学习中」+「N3 已掌握」时，N3 词不再作为新词推送
- 但 N3 词在 N2 例句中出现时仍要给假名注音（因为该词出现在更高等级例句中说明它对当前用户仍是新的）

### 5.4 业务含义

各等级约 1000–1500 词，全等级合计 5000–7000 词。这意味着：
- 数据生成可以分等级渐进，不必一次跑完
- 每个等级独立做 quality 验证
- 商业上可以做「免费 N5/N4，付费 N3-N1」的分层（如果走付费方向）

### 5.5 词量与词表来源 ⭐

当前词库来源：**Anki 红宝书 N2 牌组**（`N2/collection.anki2`），通过 `phase5/import_anki.py` 导出为 `n2_words.json`，共约 **2335 词**。

与早期 MVP 的 450 词子集相比，全量词库的变化：

- **不再区分高/中/低频**：新词候选按 `word.id`（即红宝书章节顺序）升序排列，不依赖 frequency 字段
- **字段精简**：去掉了 `romaji / meaningEn / usageNotes / antonyms / collocations / frequency`；新增 `pitchAccent?`（声调）、`homophones?`（同音語）、`audioFile?`（word-level mp3 路径）
- **音频**：单词读音 mp3 来自 Anki 牌组内置的 HyperTTS 音频（committed to `public/audio/words/<wordId>.mp3`），不再依赖 msedge-tts 实时生成；例句 TTS 仍走 `public/audio/sentences/`

**上线门槛**：N2 全量词汇（~2335 词）题目生成并通过双模型交叉验证即可发布。N3 / N1 / N4 / N5 等级扩展放到部署之后渐进生成，届时按优先级（N3 → N1 → N4 → N5）批量执行即可。

### 5.5 代码层面的可扩展点

避免硬编码 N2，所有"等级"相关的地方走配置：

```javascript
// 不要这样
const TARGET_LEVEL = 2;

// 要这样
state.settings.activeLevels = [2];  // 用户可设置数组
state.settings.dailyNewWordsByLevel = { 1: 0, 2: 4, 3: 2, 4: 0, 5: 0 };
```

## 6. 开发者模式（Quality of Life）

### 6.1 「快进到第二天」

为了：
- 开发期调试 SRS 调度
- 用户预览"明天的安排"
- 测试连续多日的体验

需提供：

- **快进 1 天**：把虚拟时间推进 24 小时，重新生成队列
- **快进 N 天**：可输入天数
- **回到真实时间**：取消快进
- **重置所有进度**：现已存在（右上角 Reset）

UI 位置：
- 放在设置页面或独立的"开发者菜单"
- 一般用户也开放（"明天会复习什么"是合理需求）
- 但不放在主导航的醒目位置（避免变成上瘾的"快进消费"）

### 6.2 实现要点

时间偏移作为状态保存：

```javascript
// state 加一个字段
state.timeOffset = 0;  // 毫秒

// 全局替换 Date.now() 为
function getCurrentTime() {
  return Date.now() + state.timeOffset;
}
```

所有 `Date.now()` 调用统一用 `getCurrentTime()`。这样快进状态会持久化到 localStorage，刷新页面也保持。

## 8. 数据生成管线

### 8.1 Phase 5 管线（5 步）

词表直接来自 Anki 红宝书牌组，不再需要富化阶段：

```
import-anki（解析 collection.anki2 → n2_words.json）
    │
    ▼
import-audio（HyperTTS mp3 → public/audio/words/）
    │
    ▼
generate-q（DeepSeek 为每词生成 R/P/U 题目）
    │
    ▼
validate-q（Qwen 独立答题，验证答案一致性）
    │
    ▼
split-json（按维度切分题目 JSON，不调 LLM）
    │
    ▼
npm run db:seed（入库）
```

### 8.3 干扰项策略

`*_to_kanji` 等四选一题的干扰项不能随机挑，要按以下策略组合：

- **同义陷阱**：意思接近但不对（如「題名 vs 表題」）
- **形近陷阱**：汉字相似（如「題名 vs 題目」）
- **音近陷阱**：读音相似（如「だいめい vs めいだい」）
- **同 level 普通干扰**：同等级随机词

每道题混合 1–2 种类型，避免"闭着眼睛都能选对"。

## 9. 路线图

> 路线图基于 2026-05 的市场竞品调研重新排序：核心差异化（R/P/U）暴露 + 听力维度 + 节奏弹性是当前最高优先级，词库扩展次之，部署与高级题型靠后。详见调研文档 `~/.claude/plans/logical-mixing-clock.md`。

### Phase 1：数据生成管线 ✅
- 写 generator + validator prompt
- Python 脚本批量跑
- 全 N2 词表富化 + 题目生成 + 验证
- 落地为 JSON 数据库

### Phase 2：原型 → 真应用迁移 ✅
- Next.js + TypeScript + Tailwind + Prisma
- SQLite（部署时迁 Postgres）
- 标准 FSRS 库 (`ts-fsrs`) 替换简化版

### Phase 3：核心差异化补强 ⭐⭐⭐（当前阶段）

> 调研结论：「言葉帖」最大风险是 R/P/U 用户看不懂、JLPT 听力维度缺位、静謐节奏对突击用户不友好。本期集中处理这三件事。

- **R/P/U onboarding**：首次启动一页式说明 + 首页常驻副标题
- **R/P/U tooltip**：Practice 页维度 pill / Library 进度条 hover 解释
- **TTS 朗读**：单词、例句一键朗读（Web Speech API，零成本）
- **听力题型**：听音选汉字 / 听音选意思（嵌入 R 维度）
- **快速复习模式**：跳过 Learn 页直接做题 / 考前突击模式
- **単語別練習（单词练习模式）**：Library drawer →「打开学习页」（带 `?from=library`）→ 学习页底部「練習する →」入口；针对单个词把题库里的所有题（含未解锁维度）走一遍，结果不计入 SRS。给「我就想攻克这一个词」的用户场景。
- **每日学习量自定义**：设置页可调 `dailyNewWords`
- **用户手动标记 R/P/U**：「这个我已经会了」可跳过初学
- **快进到第二天 / N 天**：`getCurrentTime()` 落地 + UI 入口
- **`Date.now()` 全面迁移**到 `getCurrentTime()`

### Phase 4：学习闭环 ⭐⭐

- **错题本**：连续答错 / 长期低稳定度词单独入口
- **学习日历**：日历视图 + 完成度可视化

### Phase 5：N2 全量验证（上线准备）⭐⭐

> 上线门槛：词表已从 450 词扩展为红宝书 N2 全量（约 2335 词）。完成题目生成并通过双模型验证后即可进入 Phase 6 部署。

- **`import-anki`**：解析 `N2/collection.anki2` → `n2_words.json`（约 2335 词）
- **`import-audio`**：将 HyperTTS mp3 复制到 `public/audio/words/`
- **`generate-q`**：DeepSeek 为每词生成 R/P/U 题目
- **`validate-q`**：Qwen 独立答题验证一致性
- **`split-json`**：按维度切分题目 JSON

### Phase 6：部署 ⭐

- Auth.js 接入
- 多用户数据隔离
- Vercel + Neon / Supabase 部署

### Phase 7：多等级词库扩展（部署后）⭐⭐

> 上线后渐进生成其他等级，N3 优先（中国学习者基数最大），N1 次之，N5 / N4 渐进。

- **N3 数据生成**（约 1500 词，复用 Phase 1 管线）
- **N1 数据生成**
- N4 / N5 渐进生成
- 等级筛选器（Library 页）
- 多等级并行学习（`activeLevels` 多选）
- 跨等级单词处理逻辑

### Phase 8：题型扩展与 AI 批改 ⭐

- **例句 TTS / 预录配音**
- 假名 → 写汉字（IME 输入产出题）
- 句子重组（JLPT 文法常考）
- 看情境写词
- 造句题 + AI 批改（Claude Haiku，缓存控制成本）
- 中 → 日翻译 + AI 批改

### Phase 9：长期探索

> 与「静謐」「緻密」原则需谨慎平衡，不在 v1 范围内。

- 助记法（WaniKani 风格 mnemonics，但保持克制）
- 社区卡组分享 / UGC
- 多语种 UI（英 / 越 / 印尼）
- 阅读 / 听力素材整合

## 10. 反差异化的反思

虽然本产品强调差异化，但也要警惕：

- **R/P/U 三维度** 对认真学习者是优势，对临时抱佛脚的考前学习者可能太重——所以要有"快速复习模式"作为补充入口
- **静謐风格** 可能让一部分需要外部激励的用户感到无聊——可以在设置里允许加一些（克制的）成就反馈
- **理解先行** 拉长了学一个新词的时间——可以为"已经基本认识但要复习"的词做"快速通道"，跳过 Learn 页直接做题

这些都不是 v1 要解决的问题，但要意识到。
